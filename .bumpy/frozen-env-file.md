varlock: minor
---

Add `varlock freeze` to resolve env values once at deploy time and write them to an encrypted file that ships inside your deploy artifact. With `_VARLOCK_USE_FROZEN_ENV=1` set at runtime, your app boots from that file instead of re-resolving, so config is frozen with the release and rolls back with it. Aimed at apps with no build step (Elysia, Hono, Fastify) on platforms where env vars can't be set atomically with a deploy. Use `--out -` to get the same payload on stdout when your platform takes env vars but gives you no way to ship a file. Keys that are set per instance (a platform-assigned `PORT`) can be marked `@dynamic=boot`: their frozen value becomes a default that the environment can override at boot, checked against the type recorded at freeze time, still with no varlock CLI or schema needed at runtime. `varlock run --frozen` and `varlock load --frozen` are the flag form. The file is never read unless asked for, so one left over from a local freeze changes nothing. In a monorepo package with `varlock.filter` in its package.json, the frozen file holds only the items that filter selects.
